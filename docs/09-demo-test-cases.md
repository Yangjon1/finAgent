# 9. Demo 与验收测试

## 9.1 Demo A：正常报销

员工上传一张合规发票和出差附件；PaddleOCR/解析器抽取字段，规则通过发票、重复和预算检查，系统检索制度并生成低风险建议；审批人同意后形成付款申请，付款完成后归档，审计页能看到完整链路。

## 9.2 Demo B：异常发票与人工介入

上传重复发票或税额异常材料；规则引擎明确命中原因，Agent 生成带证据的说明并暂停在 `NEED_INFO`/`HUMAN_REVIEW`。无权限用户不能审批；补充材料后可重新运行，原运行记录和审计事件保留。

## 9.3 Demo C：合同风险

上传一份缺少违约责任或争议解决条款的合同；Docling/MinerU 保留页码和段落，Qdrant 检索制度/标准条款，ContractGraph 标记高风险并定位原文；法务提出修改意见后形成新版本，复核通过后归档。

## 9.4 验收指标

| 类别 | 指标 |
|---|---|
| 功能 | 三个 Demo 可从上传走到审批/归档，状态无越级 |
| 规则 | 金额、税率、重复发票、预算和权限校验可复现 |
| Agent | 输出符合 schema；无证据或低置信度自动人工介入 |
| 安全 | 跨租户不可见；无权限无法执行审批/付款工具 |
| 可追溯 | 每次模型、工具、规则、审批动作均可按 request_id 查询 |
| 一致性 | 重复提交不重复扣预算、不重复建付款记录 |
| 性能 | 普通详情接口 P95 ≤ 500ms；异步解析有状态和失败重试 |
| 体验 | 关键页面可展示来源、风险、待办和操作反馈 |

## 9.5 最小验收清单

1. `docker compose` 服务健康，数据库迁移成功。
2. 创建用户、部门、角色和预算，完成一次正常报销。
3. 验证重复发票、超预算、无权限审批、版本冲突四个负例。
4. 完成一次合同缺条款分析并查看原文证据。
5. 导出或查询一条完整审计链，确认模型输出没有直接改变业务状态。
